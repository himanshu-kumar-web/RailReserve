# RailReserve project instructions

- Always use Java for application source code.
- Use XML layouts, not Jetpack Compose.
- Use Android SQLite for persistence.
- Follow object-oriented architecture.
- Separate UI, model, database, DAO, and service layers.
- Demonstrate encapsulation, inheritance, polymorphism, abstraction, and interfaces through meaningful implementation.
- Never introduce Java Swing or JavaFX.
- Never replace the Android project with a web application.
- Do not change package names or Gradle versions without a concrete reason.
- Do not delete working code without justification.
- Make focused changes and preserve existing functionality.
- Run a build after meaningful code changes when tools permit.
- Do not commit generated build outputs or local secrets.
- All application features should be demo-ready by 19 October.
